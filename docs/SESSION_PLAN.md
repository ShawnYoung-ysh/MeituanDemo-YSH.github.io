## 3. 每轮工作与验收

### task 1-3：数据接入与应用骨架

**实施内容**

- 建立 `assets/js/app.js`、`router.js`、`data/mockRepository.js` 和服务入口；页面通过 Promise 服务访问数据。
- 实现指定快照结构与项目存储键；首次捕获单一 anchor，将任务、时间线、评价、信用事件中的相对时间转为绝对时间，保留只读种子原文件。
- 有合法快照时优先恢复；datasetVersion 改变不覆盖已有会话；schema 不兼容或数据损坏时保留原数据并提供明确恢复入口。
- 提供带演示标记的四个导航入口、默认身份 u001、首次说明、身份切换与确认重置；后续未开发页面清晰标记状态。
- 建立一次保存完整快照的写入边界；写入失败提示临时会话。初始化失败提供重试，未知路由和缺失任务提供返回入口。

**完成条件**：首次进入可读种子；刷新后 initializedAt、截止时间和所选身份不变；切换不丢任务；取消重置不变更数据，确认重置恢复初始身份、任务和积分；仅操作本项目存储键。

**检查重点**：初始化/恢复/重置的必要自动化检查，静态与 Mock 检查；覆盖 M12–M14 的基础能力，手机结果仍待实测。

### task 1-4：手机布局与任务大厅

**实施内容**

- 建立颜色、字号、间距等设计变量，以及通用按钮、卡片、状态标签和导航样式；以 390px 单列为基线，桌面居中。
- 首页展示类别、关键词、取件地点筛选及清空入口，卡片明确显示取送点、酬谢、截止时间与紧急程度；主要列表只展示可接任务。
- 读取列表时处理 open 过期；已接单任务超时只标记，不自动关闭。
- 做好加载、无结果、空列表与长标题显示；返回大厅保留筛选和滚动位置。
- 从第一版加入安全区、自然滚动、可见焦点、触控尺寸和允许缩放的 viewport。

**完成条件**：组合筛选结果正确、清空可恢复；卡片入口可点击；390px 无横向溢出，320px 做初步回归；无结果时可自行恢复。

**检查重点**：大厅筛选与到期行为；M02、M03、M05、M06、M15 的桌面布局预检，不能记为真机通过。

### task 1-5：任务详情与发布

**实施内容**

- 详情展示说明、地点、时间、金额、演示发布者资料、状态及时间线；可操作项由服务计算。
- 发布表单覆盖类别、标题、描述、取送点、截止时间、酬谢；商品预算按类别需要单列，不与酬谢混算。
- 按原方案校验标题 4–60 字、描述 10–500 字、截止时间距当前 10 分钟至 24 小时、酬谢 0–50 元且最多两位小数，金额保存为整数分。
- 提供截止时间快捷选项；错误定位到字段且保留输入；提交按钮置于表单流中，输入字体不小于 16px。
- 发布使用 requestId，服务校验与按钮禁用同时生效；成功后只创建一条任务并进入详情。所有用户输入按纯文本渲染。
- 返回未提交表单时提供本次会话内的输入保留或明确离开提示；不要求本轮实现长期草稿。

**完成条件**：u001 能发布并在大厅和详情找到新任务；无效表单不产生任务；快速重复提交不会创建多条；输入 HTML 仅显示文本。

**检查重点**：字段边界、金额解析、重复发布；M04、M07、M19、M20 的浏览器预检，软键盘实测留到 task 1-10。

### task 1-6：任务状态与信用入账

**实施内容**

- 在 taskService 中集中实现接单、取消、开始、退出、交付、确认与异议，并接入详情页操作。
- 按任务内 publisherId/runnerId、校区、信用、截止时间与 revision 校验权限和状态；UI 隐藏按钮不能替代服务校验。
- 接单、取消、退出等按规则确认；交付必填说明，异议必填原因；退出后清除 runnerId，根据截止时间回到 open 或 expired。
- 每次状态变更更新 revision 和时间线；旧页面操作失败给具体原因并刷新可执行动作。
- **确认完成时同步写入 completed 与唯一 task_completed 信用事件**，接单者 +2、封顶 100；两者作为一个快照保存。
- 以 processedRequests 保证同 requestId 重试返回原结果；不同 requestId 重复确认也受状态与唯一事件约束。
- 增加状态转换、角色权限、幂等和信用事件必要自动化测试，接入项目检查入口。使用可控时钟验证截止边界。

**完成条件**：t001 可按 u002 接单→开始→交付、u001 确认完成；t007 确认使 u004 从 75 到 77，重试不继续加分；自接、低信用、越权、过期、旧 revision 均不能非法更新数据。

**检查重点**：M08–M11、M15；信用写入本轮完成，task 1-8 只补展示与评价，不再次发放信用。

## 4. 每次对话的统一交接方式

1. 开始时读取本清单当前状态、最近变更记录及相关规范，核对工作区和上轮未完成项，再实施当前工作包。
2. 先完成可运行的交付物，同轮完成与改动相关的必要检查；业务规则变更同步原方案或 Mock 文档。
3. 结束前更新本表状态与下方执行记录，并更新 CHANGELOG。验收记录明确区分自动化、桌面模拟、真机和线上验证。
4. 有缺陷记录“触发步骤、预期/实际、严重程度、处理结果、复测证据”；截图和日志放入 `artifacts/task-1-N/`，敏感内容不公开。
5. 每轮回复给出：已完成内容、验证结果、仍有限制、下一轮任务号。只有存在实际提交才记录提交号；未提交工作注明“工作区变更”。
