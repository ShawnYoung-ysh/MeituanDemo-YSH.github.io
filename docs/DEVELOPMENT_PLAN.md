# 校园跑腿互助平台 · 开发交接方案

版本：1.0｜日期：2026-10-18（北京时间）｜对应任务：task 1-2

本文件是后续开发的执行基线，不代表功能已经实现。当前线上仍为占位首页，开发预览、Git 上传、GitHub Pages 自动发布流程已验证。

固定作品地址：<https://shawnyoung-ysh.github.io/MeituanDemo-YSH.github.io/>

## 1. 交付目标与边界

面向大学生，以手机浏览器访问为主要场景。在评审者进入网站后的约 3 分钟内，展示“发现需求 → 发布或接单 → 跑腿进度 → 确认完成 → 信用积累”的完整流程。

本期交付响应式 H5 网页，共用一套页面兼容 Android 和 iOS；无需安装 App。维持现有原生 HTML/CSS/JavaScript 与 GitHub Pages 部署。后续需要原生 App、PWA 安装或小程序时单独评估，不挤占本轮闭环和手机验收时间。

用户进入后直接使用演示身份，页面常驻简短的“演示模式”提示。首次说明数据虚构、修改保存在本浏览器；“切换演示身份”和“重置演示”放在“我的”中，重置需确认。不能将演示身份显示成真实校园认证。

## 2. 使用场景与产品选择

| 场景 | 痛点 | 本期设计 |
| --- | --- | --- |
| 课间找人代取快递 | 时间紧，不知道谁愿意帮忙 | 首页展示截止时间、取送位置、酬谢；支持类别和校区位置筛选 |
| 路过驿站或食堂顺手接单 | 不想为一单绕远路 | 用校内地点标签筛选；无需定位权限和地图接口 |
| 首次和陌生同学交易 | 不清楚是否可靠 | 演示资料卡、完成记录、评分与可解释的信用记录 |
| 已接单后等待 | 不知道任务进行到哪一步 | 清晰状态和时间线，每个阶段只有对应角色可执行的操作 |
| 手机碎片时间操作 | 表单长、按钮小、键盘遮挡 | 单列卡片、精简发布表单、触控按钮和安全区域适配 |

首版类别：代取快递、代买物品、打印代办、其他互助。找座需求可以使用“其他互助”发布座位信息协助；长期代占公共座位不作为核心卖点，实际校规约束留待真实运营阶段确认。

## 3. 信息结构与优先级

底部导航为“任务大厅 / 发布 / 我的任务 / 我的”。详情和评价是二级页面。入口示例：`#/hall`、`#/publish`、`#/tasks`、`#/me`、`#/task/t001`。

| 优先级 | 页面或模块 | 必须实现的内容 | 完成标准 |
| --- | --- | --- | --- |
| P0 | 任务大厅 | 类别、关键词、地点筛选；紧急程度；任务卡片；空结果 | 筛选结果正确，清空筛选可恢复；只把可接任务作为主要列表 |
| P0 | 任务详情 | 描述、位置、截止时间、酬谢、发布者、状态、信用提示 | 自己发布的任务不可接；过期或已接任务不可重复接 |
| P0 | 发布任务 | 类别、标题、描述、取送点、截止时间、酬谢；明确演示提交 | 表单校验有具体提示；发布一次生成一条任务并进入详情 |
| P0 | 我的任务 | “我发布的 / 我接的”切换、状态过滤、进度时间线 | 操作后大厅、详情、我的任务同时更新 |
| P0 | 接单与完成 | 接单确认、开始跑腿、提交完成、发布者确认、提出异议 | 按角色与状态限制操作；重复点击不造成重复任务或积分 |
| P0 | 信用与评价 | 信用分、规则、变动明细；完成后双方各评价一次 | 一次确认只增加一次信用；评论不重复累加信用 |
| P0 | 演示工具 | 切换身份、重置数据、首次提示、刷新保留 | 同一设备可演示双方角色；重置后回到同一初始场景 |
| P0 | 手机适配及上线 | 安全区、键盘、横竖屏、子路径、公开访问 | 通过 MOBILE_ACCEPTANCE.md 中的发布门槛 |
| P1 | 体验增强 | 草稿、站内模拟通知、收藏、更多排序 | P0 验收通过且有时间才实现 |
| P2 | 真实运营能力 | 登录、校内认证、数据库、支付、实时消息、定位、运营后台 | 另立开发阶段，不用前端 Mock 伪装实现 |

## 4. 状态与角色规则

每个用户既可发布也可跑腿；不能接自己的任务。发布者和跑腿者由任务记录决定，不能只用当前页面的“角色”按钮决定权限。演示身份切换不是安全认证。

| 当前状态 | 操作与执行人 | 下一状态 | 条件和副作用 |
| --- | --- | --- | --- |
| open（待接单） | 非发布者接单 | accepted | 同校区、信用分 ≥60、未截止、尚无接单者；记录 runnerId |
| open | 发布者取消 | cancelled | 二次确认；不增减信用 |
| open | 到达截止时间 | expired | 读列表和提交接单时均检查截止时间 |
| accepted（已接单） | 接单者开始 | in_progress | 写入时间线；本期不自动扣款 |
| accepted | 接单者退出 | open 或 expired | 二次确认；清除 runnerId；超过截止时间则 expired；不自动扣信用 |
| in_progress（跑腿中） | 接单者提交完成 | awaiting_confirmation | 填写交付说明；发布者尚未确认前不得计为完成 |
| awaiting_confirmation（待确认） | 发布者确认 | completed | 原子更新任务与信用事件；接单者 +2，封顶 100 |
| awaiting_confirmation | 发布者提出异议 | disputed | 必填原因；不增加信用；展示“演示中待处理” |
| completed（已完成） | 双方评价 | completed | 每个任务每个作者仅一次；1–5 星；不额外改变信用 |

取消、过期、争议均不自动扣分。争议终态的运营仲裁留待 P2，演示版不伪造自动裁决。已接单或进行中的任务超过截止时间仅标记“已超时”，不突然从任务列表消失或自动结单。用户再次点击已失效操作时，显示具体原因并刷新可执行按钮。

信用规则是本项目的演示设计：`min(100, creditBase + 信用事件增量之和)`。评分、完成数量、信用分分开显示。creditBase 是虚构历史基数；只有明确的完成事件增分，不从评价星级推断信用。低于 60 的测试身份可发布任务但不能接单。

## 5. 表单和交互约定

- 标题 4–60 字，描述 10–500 字；去除首尾空白，不能为空白字符。
- 校区和地点从演示地点列表选择，不收集真实学号、手机号、宿舍门牌或取件码。
- 截止时间必须在当前时间 10 分钟至 24 小时之间；同时提供“30 分钟 / 1 小时 / 2 小时”快捷选择。
- 酬谢 0–50 元，最多两位小数，存储为整数分；商品预算另列，演示中不实际支付。
- 校验失败时保留输入，提示定位至字段；提交成功后展示任务详情和明确反馈。
- 所有描述和评论按纯文本渲染，禁止将输入作为 HTML 注入。
- 重复点击期间禁用按钮；服务层再次校验角色、状态、revision 与 requestId。
- 返回列表保留筛选和滚动位置；未知路由给出返回大厅入口。
- 不要求悬停、长按或滑动才能发现核心功能；按钮必须有文字或可访问名称。

## 6. 手机优先的技术方案

### 布局与浏览器目标

项目目标：iOS 16+ Safari、Android 10+ 的常用 Chrome/Edge；真实兼容范围必须以实际测试设备为准。微信内置浏览器列为补充验证，不能因测试了桌面 Edge 就宣称已支持 iOS。发布时记录实际 OS 和浏览器版本。

使用流式单列布局，以 390 CSS px 设计，验证 320、360、375、390、412、430 px。平板和桌面保留居中容器，最大内容宽度约 720px，可在 ≥768px 时将列表扩展为两列；表单与详情仍控制阅读宽度。断点服务于内容，不按手机型号写分支。

设计基线：正文 16px，辅助文字至少 12px；主要按钮和导航点击区域至少 44×44 CSS px，主操作高 48px；间距以 4/8px 递进；可见焦点、文本错误提示、足够对比度。44px 是本项目触控目标，高于 WCAG 2.2 的最小目标尺寸要求。[W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)

### iOS 安全区与 Android 键盘

建议页面 viewport：

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover, interactive-widget=resizes-content">
```

`viewport-fit=cover` 与 `env(safe-area-inset-*)` 配套使用；底部导航和详情操作条增加底部安全区，主内容预留等量空间。横屏同时照顾左右安全区。保留用户缩放，不设置 `user-scalable=no`。[WebKit 安全区说明](https://webkit.org/blog/7929/designing-websites-for-iphone-x/)、[MDN viewport](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/meta/name/viewport)

优先使用文档自然滚动和 `min-height`；高度先给 `100vh` 回退，再用支持检测启用 `100dvh`。不把整页固定成一个不可滚动的高度。

软键盘处理不能仅依赖 `interactive-widget`，各浏览器行为不同。发布页的提交按钮放在表单流中；输入时底部导航可收起，保证聚焦字段可滚动到可见区域。必要时用 `visualViewport` 做渐进增强，缺失时仍可完成表单。真机检查键盘弹出、收起和地址栏折叠后的位置。[Chrome Android 视口与键盘说明](https://developer.chrome.com/blog/viewport-resize-behavior)

表单输入字体至少 16px；金额用文本输入配合 `inputmode="decimal"` 和显式格式校验。日期不要依赖 `new Date('2026-10-19 12:00')` 等非标准字符串，使用毫秒时间戳或含时区的 ISO 时间；提交截止时间时再次校验，UI 清晰展示本地时间。

### 文件与模块建议

```text
index.html
assets/css/tokens.css, app.css, mobile.css
assets/js/app.js, router.js
assets/js/pages/          # 大厅、发布、详情、我的任务、信用
assets/js/components/     # 卡片、导航、表单反馈、确认弹窗
assets/js/services/      # taskService、creditService、reviewService
assets/js/data/           # mockRepository；未来替换 apiRepository
mock/db.json             # 公开只读的虚构初始数据
docs/                    # 开发、数据、验收及提交记录
scripts/                 # 预览、检查、发布
```

页面只调用服务，不直接读写 localStorage 或散落 fetch。服务返回 Promise，便于后续切换后端。状态更新先在副本中完成校验，再一次保存完整快照，成功后刷新 UI；存储失败明确提示“当前为临时会话”，不可提示已永久保存。

所有资源相对路径加载；Mock 使用 `new URL('./mock/db.json', document.baseURI)` 读取。锚点路由保证 GitHub Pages 子路径下直接打开、返回、刷新有效。

## 7. 数据与未来后端

已提供 `mock/db.json` 和 [MOCK_DATA.md](MOCK_DATA.md)。首次进入加载种子，将相对时间转换成当前会话时间，写入带版本号的 localStorage。普通刷新只恢复快照，不重新移动截止时间；手动重置才重新生成初始场景。

数据修改只作用于同一浏览器配置文件和网站源。不同手机、不同浏览器之间不共享；同一浏览器同源多标签可监听 storage 事件提醒刷新，但 Mock 不保证并发抢单的原子性。不得把 GitHub Token 写进前端以便访客“写回数据库”。GitHub Pages 提供静态托管，不是可写业务数据库。[GitHub Pages 能力](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

未来真实多人版需单独增加服务器身份认证、数据库事务、唯一接单约束、服务端权限、审计和真实信用事件；前端继续使用当前固定域名。接口替换只落在数据适配层。

## 9. 交付和发布门槛

- 开发人员交付：源文件、Mock 数据、版本提交、已知问题、验收结果、至少一张 Android 和一张 iOS 真机截图。
- 所有 P0 核心流程通过；无阻断操作、页面空白、重复接单、重复计分等严重缺陷。
- [手机验收表](MOBILE_ACCEPTANCE.md)记录真机结果。缺少真机时状态为“待验证”，不是“通过”。
- 运行 `node scripts/check-site.mjs`、`node scripts/check-mock.mjs`；业务实现后增加状态转换与关键流程的必要测试。
- 推送到 main，确认 GitHub Pages 部署成功，再运行线上检查与 `--require-demo`；该开关只排查占位文案，不替代业务验收。
- 保持原网址、仓库名与账号名不变，仓库保持公开。提交平台只填写固定作品 URL；未取得回执不得记录为正式提交完成。

## 10. 主要风险与取舍

| 风险 | 应对 |
| --- | --- |
| 评审在不同设备打开看到不同操作记录 | 首次提示“本机演示”，每台设备自带完整种子；不声称多人共享 |
| 评审数天后打开，样例全部过期 | 首次初始化使用相对时间；普通刷新保持状态；提供显式重置 |
| Safari 键盘遮挡按钮、底部手势区遮挡导航 | 自然滚动、安全区与真机测试，优先修复，不靠锁定屏幕高度 |
| 浏览器禁用存储或存储已损坏 | 捕获异常、版本校验、临时内存模式和重置入口 |
| 截止时间紧 | 先交付 P0；消息、地图、支付、PWA 缓存延后 |
| 发布后缓存仍显示旧内容 | 页面标注版本；发布后确认实际内容，必要时为资源使用版本参数；本期不加 Service Worker |
